# 使用安全与已知边界

本文适用于当前 **v0.16.1**（无模型启发式探索 + 三档快速清理）的安全边界说明；具体 `BuildId` 的验收状态与测试范围以本次交付清单和验证摘要为准，不以源码版本号本身宣称正式发布已完成。相关说明见 [v0.16.1 说明](RELEASE-0.16.1.zh-CN.md)、[使用手册](使用手册.md) 与 [规则说明](RULES.md)。

## 一、当前适用边界：无模型启发式探索（v0.14.0–v0.16.1）

- **无模型载荷**：本版不携带、启动或复用 LLM、推理 runtime 或旧模型缓存。调度只安排已有只读探针，不执行任意脚本；工作台不提供模型开关，生产包校验无模型载荷且不启动推理进程。旧源码／实验／历史包不擅删。
- **线索不等于可删授权**：文件大小、年龄、名称、类型分布与收益／成本排序仅用于决定先检查什么，不是删除概率，也不授予处理资格。目录名 `Cache`、体积或相似案例不能解除保护；没有足够证据就明确标为未知，不能把未覆盖当作空或可清理。
- **范围与有界资源**：自动多目录调查仅在用户明确选定的范围内进行。受全局预算、显式取消、目标动作去重、无新证据停止，以及按物理内存容量与空闲内存核定的有界资源策略（安装内存 1/8、空闲内存 1/2、4GiB 三者较小值，会话记录空间预算 `512–16384 MiB`、默认 `512 MiB`、保留至少 `256 MiB` 磁盘余量）约束。`Partial`／覆盖不足、身份变化、云／链接拒绝不得以“继续探索”为由放宽。
- **保护与分级复核**：个人文档、照片、数据库、源码、混合整体与系统／便携程序保持保护；可信项目的精确生成子集与整个项目根分开复核。通用重复包、大文件与 Simple Cache v5 试点仅作展示，不自动留一删余或进入回收。网络映射盘、其他账户、系统内部、重解析／云占位与未知元数据分别拒绝或记未覆盖，不提权补访问、不主动下载云文件。
- **正向批准与只回收链**：建议默认不勾选；生成复核清单采用后台作业，可取消，且复用精确文件集合、任务／观测／分析代绑定、`DisplayHash`、私有 ACL／DPAPI、单次执行防重放、逐项执行前复查与只回收链。重新分析或目标变化使旧草案／批准失效，目录内新增文件不继承旧批准；中断或异常状态不伪造完成或未开始，不可回收时不得静默永久删除，未知结果不自动重放。
- **空间语义**：空间排行为递归已观察量，各目录相互包含不能相加；硬链接去重语义、未知分配与覆盖缺口须明确，所有字节不冒称可释放。
- **当前验证边界**：自动与开发期回收验证仅在自有人工 GUID 沙箱／受控测试对象上执行（本轮含自有人工夹具的受控成功回收验证）；**真实用户缓存清理、真实非空回收站清空、真实 UAC／DISM 系统维护、完整多 DPI／多显示器矩阵及大规模真实文件内容分析仍未实跑**。历史版本记载的未测范围仅代表当时状态，既不冒充本轮已实测真实系统，也不代表将正常功能界定为永久未授权。

## 二、当前适用边界：快速清理（三档预设与附加入口）

当前快速清理沿用自 v0.11.0／v0.12.0 建立的三档预设、精确纯缓存白名单、缓存位置发现授权与独立系统维护入口契约，并与深度探索独立执行。

### 零保留期的范围

High 档只对经精确模板审核的纯缓存使用 0 小时保留期：Chrome／Edge／Brave 的 `Cache`、`Code Cache`、`GPUCache`，Firefox `cache2`，VS Code `Cache`／`CachedData`，新版 Teams 的 `Cache`、`GPUCache`、`Code Cache`，以及经典 Teams `GPUCache`。授予方式是精确模板白名单（`AgePolicy=PureCache`），不以“Cache”名称或分组自动判断。其他规则仍为正数保留期，包括 Temp（当前用户 6 小时、Windows 24 小时）、npm／NuGet／pip／Yarn／Go／Gradle 等包与构建缓存、崩溃转储和 WER 归档、显卡着色器缓存。0 小时不绕过应用关闭、占用、只读、链接、未来时间和文件身份检查。

### Teams WebView2 归属

新版 Teams 的三个缓存要求 `ms-teams`、`Teams` 均已关闭。对 `msedgewebview2`，只有明确判定归属“无关”才继续：沿父进程链核对，且只有位于受保护 Program Files 下、签名有效且签名者为 Microsoft Corporation 的宿主才判为无关，并在判定后复查进程创建时间以排除 PID 重用。归属未知、父链变化、链接路径或权限不足一律保守拒绝，不读取命令行，不结束进程。进程存在或不存在、文件未被占用，都不是独立的安全证明。npm、Python、Java 等共享运行时无法证明无关，保留原名称守卫；本版不宣称全面解决误跳过。

### 缓存位置发现与授权

- **来源**：只有当前进程的环境变量 `NUGET_HTTP_CACHE_PATH` 和 `PIP_CACHE_DIR`。不遍历任意配置文件（如 `nuget.config`、`pip.ini`），不执行 Python、pip 或 NuGet，不接受用户输入任意路径，也不扫描任意目录。这两个变量也可能指向无关目录，因此发现只是候选，不是许可。
- **范围**：只识别受支持的精确缓存布局（NuGet HTTP；pip 的 `http`、`http-v2`、`wheels` 子根）。无法证明布局的位置显示为不支持，不会进入规则。
- **展示绑定**：确认时提交的是用户所见内容的绑定值（来源、规范化后的来源值、精确路径、目录身份、模板）。若确认时当前绑定与展示时不一致，授权被拒绝，需刷新后重新确认。
- **失效与撤销**：环境变量值、目录身份（如目录被替换）、布局或策略变化后，原授权显示为“已失效”，不会被用于清理，需重新确认；发现源不再存在的旧授权同样不可清理。用户可在“发现缓存位置…”中撤销已保存的授权；保存、撤销或发现范围变化都会使当前扫描计划失效，必须重扫。
- **执行与保存**：Worker 只接受规则 ID，不接受 Root，并独立重新发现与核对授权、绑定、来源值和目录身份，任一不符即拒绝。授权保存在状态根下由 DPAPI 保护的 `cache-authorizations-v1.dpapi`；DPAPI 和私有 ACL 不构成同用户恶意程序的隔离边界，也不能授予管理员权限。

### 系统维护与 DISM

系统维护是独立高级操作，不属于文件清理规则，不统计为候选文件或已释放空间。唯一动作是系统 DISM 的 `/Online /Cleanup-Image /StartComponentCleanup`，不含 `/ResetBase`，不支持任意命令参数。流程是先显示说明，用户确认后才请求 UAC，并直接启动系统目录下的 `dism.exe`。**独立提权只作用于该 DISM 进程，不提升本清理器、脚本或用户可写的任务文件**，文件清理仍以普通权限运行。

风险：旧组件可能被立即删除，没有自动维护任务的 30 天缓冲，可能影响更新回退；运行时间可能很长，无法事前精确统计释放量，也没有原子回滚。工具不会使用 `/ResetBase`、手动删除 WinSxS／Installer、停止更新服务、自动重试或强杀 DISM。打开说明窗后取消，不触发 UAC 或 DISM。

### 清理前提示

先备份重要内容，确认规则、候选与处理方式。默认移入回收站；选择永久删除或清空回收站可能无法恢复。应用关闭条件满足和文件够旧，不等于所有内容都没有价值。

### 已实现的快速清理约束

- 只接受内置规则实例，不提供任意路径、全盘后缀、其他账户或系统组件存储删除。
- 扫描记录完整候选和文件身份；计划包含哈希、规则快照和用户级保护的元信息。
- 清理前整计划重新审批，逐文件复核模式、年龄、大小、时间、身份与完整祖先路径；只读／变化／链接／权限失败时跳过。
- 预览索引只用于显示和筛选，不替代清理授权。计划单次执行，旧版本任务需重扫。
- 文件清理默认不提权、不修改文件权限、不结束用户进程；唯一的提权入口是上文独立确认的系统维护，且只提升系统 DISM。
- 三档使用区分大小写的 `Low` / `Medium` / `High`（历史 v0.10.0 为 `Recommended` / `Deep`）；高档不绕过进程、身份或祖先路径检查，Temp 独立下限为当前用户 6 小时、Windows 24 小时。
- 选择档位即应用；切换档位使当前已知旧计划写入拒绝标记，预览失效，即使切回也需重扫。旧计划缺少档位／策略字段或使用旧档位名时安全拒绝，不迁移或改写候选数据；内部状态根仍使用 `v3`。
- 高级自定义默认关闭，重启后不会自动启用。旧 `preferences-v3.json` 只迁移为低档预设并提示，不沿用旧可选勾选，旧文件保留；新偏好写入 `preferences-v4.json`。
- 内置固定规则遇到缓存覆盖变量时仍只导致对应规则 `UnsupportedConfiguration`（配置不受支持）并保留文件，不采纳变量提供的新根（仅 NuGet HTTP 与 pip 可经上文“缓存位置发现与授权”确认）。应用运行中为 `RunningProcess`；缺失目录为 `Missing`，不是已清理。
- 包缓存只恢复官方确认的精确子根，仅高档预设纳入；Firefox 仅 `cache2`，永不把 SQLite WAL/SHM 当缓存；新版 Teams 只处理三个固定 WebView2 缓存子目录，归属未知时保守拒绝。

## 三、不能保证的内容与隐私边界

- 文件名检查到删除仍有时序窗口；同权限恶意代码不是本应用的隔离边界。
- 缓存可能包含离线工作需要的内容；删除可引发重新下载、编译。新版 Teams 缓存清理后需重新获取网页资源和编译脚本，离线时可能受影响。
- 高档包含崩溃转储和 WER 归档：这些诊断资料不可重建，删除后会失去历史故障证据。不需要时请选低档或中档。
- 规则只覆盖已支持的默认目录，不涵盖所有应用版本和自定义布局；部分云盘／重解析目录、UNC、ADS 和特殊／超长路径保守拒绝或不兼容。
- 回收站移动大小是逻辑大小，不代表立刻释放磁盘空间。
- 开发构建与候选包未签名；不要为了运行程序关闭系统安全防护。
- **日志与隐私**：应用不上传文件，但本地计划／日志包含路径、文件大小和时间。状态目录为当前用户和 SYSTEM 权限，不防御同用户的其他程序。日志、任务及 SelfTest 证据不会全部自动清除，对外提供错误信息或日志前请先检查私人路径，优先使用深度探索“记录与帮助”中的脱敏问题报告（不要公开上传用户文件、完整私有路径或原始候选清单）。
