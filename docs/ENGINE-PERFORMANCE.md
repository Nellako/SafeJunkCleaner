# 引擎测量方法与本轮性能事实

## 结论

**事实：首批顺序样本更慢；完成最小热点补丁后，本轮ABBA交错样本没有重现扫描/复核删除的明显退化，但仍不足以证明稳定整体加速。** ABBA每版本仅2轮，A1明显慢于其余轮次、可能受预热和残余负载影响；连续预览页的B中位数反而更慢。不能只选有利阶段或以分页速度宣称整体优化成功。原始两批数据均保留，详见下表。

### 能够与不能够得出的结论

- 本批B扫描/复核删除中位数比A低约23.5%/14.1%，**仅描述本批观测**，不等于稳定性能收益；A2扫描13.31秒、复核删除22.96秒，已与B1/B2相近，A1的21.51/30.81秒拉高了A中位数，不能隐去这点。
- 连续页B约12.96ms对A7.63ms，相对更慢约69.9%，绝对差约5.3ms；首次页约相同。不得只突出扫描下降而省略页面退化。
- 本轮没有重现首批万文件扫描/复核删除的大幅退化，但样本太少，不足以断言已查清首批退化根因，也不足以宣布整体优化成功。
- 窗口不是严格无干扰：主代理报告verifier的轻量G03（34断言）可能与ABBA重叠；系统/防护/磁盘缓存/后台负载无法完全管控，ABBA仍不能消除所有预热与时序影响。未因该限制无限重跑。
- 测量对象仍仅为128B平面人工文件、2条同根规则；不推广至所有用户缓存、磁盘或应用布局。日志、人工沙箱元信息与全部JSON保留。

## 本轮静态优化与热点

- 扫描按根缓存操作内不可变规则数组rootPairs，替代文件循环中的同一哈希表重复查找；同根目录仍仅枚举一次，候选仍去重。没有缓存安全判断、进程状态、文件身份或祖先检查。
- 路径、属性、进程、文件身份、只读、mtime/size、独占打开、最终身份复核均未移除，无盲目并发。
- 第一批样本中的清理配置复核在每个文件经过函数/PSObject.Properties反射，空配置也付调用成本。第一批完成后，经主代理批准追加安全等价补丁：从重新审批规则预建变量名数组，清理循环直接遍历；空数组免函数/反射，非空仍逐文件读取当前环境变量，不缓存值或结论，不改变检查语义。首批after JSON不代表此补丁性能；上述B冻结版包含此补丁，ABBA已按主代理窗口运行。
- Get-SjcContextConfiguration/ProfileEpoch不在扫描的逐文件热循环；ProfileEpoch仅预览页边界一次。不能把全部扫描退化归因于档位字段。

## 尚未完成的分阶段与场景

- `RevalidateAndDeleteMs`仍合并整计划验证、逐文件检查和实际删除，**未分解独立删除I/O耗时**；不为计时绕过正常删除入口或削弱检查。未来可加入只读仪表钩子单独累计，但本轮没有实现。
- 未完成长路径、多根大量规则/多Profile、大文件、慢盘、取消/锁定/只读跳过比例等性能矩阵。安全回归覆盖不等于这些场景的性能已测量。
- 不使用旧v2.2.1真实环境引擎做清理对比；旧脚本只用于规则语义清单。性能对照为本轮修改前模块化引擎。
- 这不是最终验收；须由code-verifier实际独立运行安全契约/回归。若受控交错样本仍显示退化，应优先处理可证冗余，而不是牺牲安全获得数字。
