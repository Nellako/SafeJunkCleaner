# v0.12.0 引擎扩展候选

本文保留 v0.12.0 开发候选的范围说明。完整预验收现已通过；最终固定提交、产物和本地交付状态以 [v0.12.0 验证记录](VALIDATION-0.12.0.md)、本地发布清单与 LATEST 为准，不以本文原始冒烟记录判断。保持原有弹窗流程，在高级自定义内加入“发现缓存位置…”与“系统维护…”入口。

## 可试用的变化

- 高档的精确纯缓存白名单使用零保留期：Chrome/Edge/Brave Cache、Code Cache、GPUCache，Firefox cache2，VS Code Cache/CachedData，新 Teams 三个精确缓存及经典 Teams GPUCache。仍须关闭相关应用；未来时间、只读、占用、链接、身份变化仍跳过。
- Temp、包／构建、诊断及显卡着色器继续正数保留期，不把整个“缓存”分组无差别清空。
- 新 Teams 的 WebView2 进程归属可明确判为无关时不再整类阻断；无法证明归属时继续跳过。npm/Python/Java 宿主未全面细化，不宣称取消所有误跳过。
- 仅从当前进程环境变量 `NUGET_HTTP_CACHE_PATH` 与 `PIP_CACHE_DIR` 发现受支持的精确缓存布局；不遍历任意配置文件，不执行外部包管理器，不接受任意路径输入。未确认位置不进入规则；首次确认绑定展示时的目录指纹，来源／路径／身份变化须重新确认。旧或消失授权可撤销。
- 系统维护唯一动作是 Windows 自带 DISM 组件清理，不带 ResetBase。普通清理器不提权；用户单独确认后，直接请求提升系统 DISM。旧组件可能立即删除，可能影响更新回退；时间及释放空间不作保证。

## 人工验收建议

1. 正常打开程序，高级草稿内能看到两个新入口，取消草稿不改变主清理范围。
2. 先查看高档说明与扫描候选；纯缓存保留期应为0小时，Temp等不为0。
3. 如配置了 NuGet/PIP 覆盖路径，查看发现清单、支持原因和精确目录；不支持布局不会被自动授权。
4. 系统维护可先只打开说明窗并取消，无需为了界面验收运行真实维护。

授权/系统维护是实际状态修改；确认后才执行，不因打开窗口自动操作。发现没有候选不代表该应用没安装，只表示当前支持的覆盖来源没有匹配项。
