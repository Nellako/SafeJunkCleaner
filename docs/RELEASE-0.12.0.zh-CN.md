# v0.12.0 中文版发布说明

本次为本地交付，不创建线上 Release。完整预验收已通过 Core 28／28、1106 断言及 Release 34／34、1305 断言。最终产物还须通过固定提交的重新构建、回归、实际桌面验收及晋级门禁；是否已完成交付以父目录 `releases/LATEST.json` 和对应发布清单为准。初次失败、修复与未测边界见[验证记录](VALIDATION-0.12.0.md)。

## 这份候选带来什么

v0.12.0 在保持已认可的单界面流程的前提下，扩展清理引擎本身，主要集中在"哪些缓存可以被清理"和"如何证明可以清理"两件事上。

- **高档的精确纯缓存白名单使用零保留期。** Chrome／Edge／Brave 的 Cache、Code Cache、GPUCache，Firefox cache2，VS Code Cache／CachedData，新版 Teams 的三个精确缓存，以及经典 Teams GPUCache，在高档下不再按年龄保留。Temp、包与构建缓存、崩溃转储与 WER 归档、显卡着色器缓存仍是正数保留期。
- **支持从覆盖环境变量只读发现缓存位置。** 可为 NuGet HTTP 缓存和 pip 的受支持缓存布局发现不在默认位置的目录，需用户确认后才进入规则。
- **新版 Teams 的 WebView2 进程归属可判定时不再整类阻断。** 归属无法证明时仍然跳过。
- **新增独立的系统维护入口。** 唯一动作是 Windows 自带的 DISM 组件清理，不含 ResetBase。

弹窗前端与已有清理流程未改动；两个新入口位于高级自定义内。

## 零保留期到底覆盖哪些

零保留期**只**授予精确审核过的纯缓存模板白名单，依据是精确模板 ID，不是"名字里带 Cache"，也不是整个分组被清空。不在白名单内的规则一律保持正数保留期，包括经典 Teams Cache、Steam htmlcache、临时文件、包与构建缓存、诊断资料和显卡着色器缓存。

零保留期只是取消年龄下限，其余安全检查一项都不会绕过：应用必须已关闭，文件不会被占用，不修改只读文件，不跟随链接，不处理时间戳在未来或身份已变化的文件。

## 发现缓存位置

发现是只读的，来源限定为**当前进程的环境变量** `NUGET_HTTP_CACHE_PATH` 和 `PIP_CACHE_DIR`。工具不会遍历 nuget.config、pip.ini 等配置文件，不执行 Python、pip 或 NuGet，不接受你手动输入任意路径，也不扫描任意目录。

发现结果不是清理许可。只有你确认过的位置才会进入规则，且授权与展示内容绑定：

- **绑定**：确认时提交的是你当时看到的内容——来源、规范化后的来源值、精确路径、目录身份和模板。
- **失效**：环境变量值改变、目录被替换、布局或策略变化后，原授权显示为已失效，不再用于清理，需重新确认。
- **撤销**：可随时撤销已保存的授权。保存、撤销或发现范围变化都会让当前扫描计划失效，必须重新扫描。

清理阶段由 Worker 独立重新发现并核对授权、绑定、来源值和目录身份，任一不符即拒绝；Worker 只接受规则 ID，不接受任意根目录。

授权保存在状态根下由 DPAPI 保护的文件中。DPAPI 与私有 ACL 不是针对同用户恶意程序的隔离边界，也不能授予管理员权限。

## 新版 Teams 与 WebView2

新版 Teams 的三个缓存要求 ms-teams 和 Teams 均已关闭。对 msedgewebview2，只有在沿父进程链核对、且确认宿主位于受保护的 Program Files 下、签名有效且签名者为 Microsoft Corporation 时，才判为归属无关并继续；判定后还会复查进程创建时间以排除 PID 重用。归属未知、父链变化、权限不足或签名无法证明时一律保守拒绝。工具不读取命令行，也不结束任何进程。进程存在或文件未占用，都不构成独立的安全证明。npm、Python、Java 等共享运行时未取得可证明无关的依据，保留原有守卫；本版不宣称全面解决误跳过。

## 系统维护

系统维护是独立的高级操作，不属于文件清理规则，不计入候选文件或已释放空间。唯一动作是系统 DISM 的 `/Online /Cleanup-Image /StartComponentCleanup`，不含 `/ResetBase`，不支持自定义命令参数。流程是先显示影响说明，你确认后才请求 UAC 并直接启动系统目录下的 dism.exe。**独立提权只作用于该 DISM 进程，不会提升本清理器、脚本或可写的任务文件；文件清理仍以普通权限运行。**

风险需要事先知道：旧组件可能被立即删除，没有自动维护任务通常具备的 30 天缓冲，可能影响更新回退；运行时间可能很长，事前无法精确统计释放量，也没有原子回滚。工具不会使用 ResetBase、手动删除 WinSxS 或 Installer、停止更新服务、自动重试或强杀 DISM。打开说明窗后取消，不会触发 UAC 或 DISM。

## 验证状态

- 初次 Core 基线 25 用例中 9 失败、821 断言中 27 失败，已迁移旧期望并补齐边界测试。修订后完整 Core 28／28、1106 断言，完整 Release 34／34、1305 断言，均通过。
- 修复 TestMode 上下文限制、失效授权重新确认、维护完成/异常状态释放及 3010 重启提示；发布与晋级统一要求 8 个源码模块和 12 项桌面检查。最终交付仍须以固定提交后的真实证据链为准。
- 已由主对话在人工沙箱中初步观察：主窗口（v0.12.0，450 个候选）、两个新入口，以及取消高级草稿后原范围与扫描不变。**这只是初步诊断，不是最终构建验收。**
- 尚未验证：真实缓存删除、真实回收站清空、真实 UAC 与 DISM、完整多 DPI／多显示器场景。
- EXE 未签名。
