# 清理器下一轮迭代决策

日期：2026-11-03。状态：v0.10.0 开发候选已完成，Release回归28/28、734断言通过；有限实际窗口观察完成，详见[v0.10.0 验收记录](VALIDATION-0.10.0.md)。v0.10.0 是当前正式稳定版本。v0.11.0 为本地开发候选，实现与验收进行中，见文末“v0.11.0 补充决策”及[v0.11.0 验收记录](VALIDATION-0.11.0.md)。

## 已确定

1. **结论：以 v2.2.1 对比当前 v0.9.0，V3.0 快照追踪变化。** 理由：用户确认对比基线；区分真正删除、路径修正、默认关闭和发现差异。
2. **结论：只修改 develop，保留独立 main 仓库，通过验收后单向本地快进晋级。** 理由：用户选择本地发布晋级而非远程或双向镜像。本轮不授权自动提交、真实晋级、配置 remote 或对外发布。
3. **结论：保留本决策记录。** 理由：用户要求记录取舍，避免后续迭代反复推翻需求。
4. **结论：恢复旧版立绘应用图标，透明部分合成纯白方形背景。** 理由：用户明确要求保留旧品牌图形并加白底；用户声明本人原创或拥有覆盖应用及源码分发的相应权利。此项是用户权利声明，不是第三方独立认证。保留主体比例与完整边缘，生成多尺寸 ICO。
5. **结论：操作图标统一采用现成 Segoe MDL2 Assets 图标体系。** 理由：避免自绘和风格混杂；不分发系统字体。操作图标不加应用图标的白底。
6. **结论：保持 PowerShell 5.1 + WPF，修复实际软件而非另做 HTML 演示。** 理由：当前问题主要是信息密度和操作表达；保留完整候选、分页、草稿及后台机制，采用紧凑表格与可见分组。
7. **结论：提供推荐／深度两档。** 理由：用户选择扩大有效清理范围并允许明确影响后确认；深度档不自动全选风险项，不绕过占用、路径和文件身份检查。档位和阈值纳入封存计划，切换要求重扫。（v0.11.0 起由低／中／高三档替代，见下文补充决策 B2。）
8. **结论：恢复和新增规则必须核实精确缓存对象，不照搬旧版错误规则。** 理由：旧 FirefoxCache2 实际匹配 sqlite-wal；风险确认不能代替对象识别。混合仓库、离线和文档数据需专门处理，不能笼统说均可重建。
9. **结论：先测量再优化，分别报告扫描、预览、导出和清理。** 理由：既有显著收益主要在预览，不应夸大为整体删除加速。
10. **结论：测试删除仅限所有权验证的 GUID 人工沙箱。** 理由：保护用户真实文件；不运行旧固定路径删除测试，不清空真实回收站。

## v0.11.0 补充决策

日期：2026-11-03。状态：本地开发候选，实现与验收进行中；正式稳定版本仍为 0.10.0。

### 已确定

- B1. **结论：改为单界面流程。** 结果以分类主表汇总，可展开分页明细，保留例外、取消保留与CSV导出继续提供。
- B2. **结论：低／中／高三档替代推荐／深度，选择即应用。** 普通使用无需逐项勾选；新用户默认中档。高档包含不可重建的崩溃转储和WER归档，界面与文档必须明示。
- B3. **结论：高级自定义默认关闭，重启后不自动启用。** Explorer图标／缩略图缓存只在高级自定义中提供，不进入任何预设。
- B4. **结论：偏好改为 v4。** 旧v3偏好迁移为低档并提示，不沿用旧可选勾选，旧文件保留，避免旧选择被扩大解释。
- B5. **结论：新增新版Teams三个固定子缓存。** 依据微软VDI部署文档的缓存取舍说明，不视为逐文件删除背书；需关闭ms-teams/Teams/msedgewebview2，其他WebView2应用运行时保守跳过，不结束进程。不纳入整根重置、Service Worker、WebStorage。
- B6. **结论：不宣称全面支持旧51项，不宣称本轮加速。** 扩大的覆盖来自预设自动纳入已有类别和新版Teams精确缓存；历史性能数据原样保留。

### 待验证
