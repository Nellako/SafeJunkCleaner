# v0.11.0 弹窗界面决策记录

用户通过等级四需求审查确认以下方案，随后要求先编写和冒烟测试，交付人工验收后再进行进一步验证与完整回归。

## 已确定

1. **结论：文件明细移为单实例非模态子窗口。**
   **理由：** 主窗口保留分类结果，避免明细挤占主体；可同时对照分类与文件。主操作栏增加“查看文件明细”，扫描结束且计划有效后可用。重复打开置前，范围变化使旧明细失效，清理过程中冻结修改。
2. **结论：高级自定义使用按钮打开草稿弹窗，确定后生效。**
   **理由：** 查看设置或取消不应导致既有扫描作废；未修改时确定也不失效。普通三档继续即选即用，并恢复对应预设。
3. **结论：分类结果真正按组展示。**
   **理由：** 分组标题替代重复的分组列，项目列名为“清理项目”，让主结果表占用主要空间。
4. **结论：部分扫描明确标示不完整和当前已发现量。**
   **理由：** 候选量不等于全部可清理量，也不等于已释放空间；有效部分计划仍可查看明细，另提供查看原因入口。
5. **结论：本轮只构建和冒烟，先交用户人工验收。**
   **理由：** 用户明确调整交付顺序。允许实现子代理，但不在人工验收前进行完整回归或宣称全面通过。保留旧候选产物，不修改 main 或正式 LATEST。
