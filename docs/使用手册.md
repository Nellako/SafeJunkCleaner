# 星梦雨垃圾清理器 v0.17.0-rc.1 使用手册

本手册面向普通用户与维护支持人员，区分主界面的**“三档快速清理”**与独立工作台的**“无模型深度探索”**。产品当前版本为 **0.17.0-rc.1**（预发布候选，安装包主程序文件名为 `星梦雨垃圾清理器_v0.17.0.exe`，界面窗口标注 RC，版本变更、WebView2／历史记录行为差异与限制另见 [v0.17.0 预发布说明](RELEASE-0.17.0.zh-CN.md)）。后台由 `explorer/` 目录下的两个独立自包含 `.NET 10` 宿主组成：**快速清理后端 `sjc-quickclean.exe`** 与 **深度探索宿主 `sjc-explorer.exe`**；版本号本身不代表所有新复核已完成，也不保证在所有电脑、目录结构或文件系统竞态下零问题。

## 先读这四点

1. **只读扫描／盘点不等于清理。** 快速清理的“开始扫描”与深度探索的“开始探索”都只做只读检查，不移动或删除文件。
2. **绝不按目录名或扩展名盲删。** 看到“Cache”、`.dll`、`.json`、`.zip` 或很大很旧的文件，都不代表可删。程序只处理经固定规则核验或结构证据闭合的精确集合。
3. **两套流程的处理方式不同，不要混淆。**
   - **深度探索只提供移入回收站，不提供永久删除。** 建议默认不勾选；必须先生成复核清单，再先后完成“第一步：确认此清单”和“第二步：移入回收站…”。
   - **快速清理**按预设档位或高级自定义规则扫描，默认尝试移入回收站；若手动选择永久删除或清空回收站，会弹出独立确认。
4. **“记录与帮助”页中的占用数字是程序自身的扫描索引，不是垃圾量。** 例如“1GB / 5GB”表示本程序保存的本地目录记录占了 1GB、当前会话允许上限为 5GB，既不是发现了 1GB 垃圾，也不是要删除 5GB 文件。

## 一、安装与启动

1. 获取对应 `BuildId` 的完整 Windows 程序包，核对校验清单后解压到**普通本地目录**（避免直接放在未同步或受限的特殊重定向目录中）。
2. 关闭正在运行的旧版程序后，启动主程序：
   - `星梦雨垃圾清理器_v0.17.0.exe`（文件名不附带 `rc.1` 后缀，程序窗口标注 RC 版本）
3. **同级必需文件与目录（缺一不可）：**
   - `星梦雨垃圾清理器_v0.17.0.exe.config`：用于打包程序启用长路径兼容。
   - `explorer/` 目录：包含共享自包含 `.NET 10` 运行时的两个独立宿主——快速清理后端 `sjc-quickclean.exe` 与无模型深度探索宿主 `sjc-explorer.exe`，无需另装 .NET SDK 或下载模型。
   - 随附说明与许可文件（如 `README.md`、`LICENSE`、`THIRD-PARTY-NOTICES.md`、`assets/third-party/PS2EXE-LICENSE.txt`、本手册及版本说明等）。
   - **本版不含 `model/` 目录**，不读取也不会启动旧版大模型组件。
4. **不要只复制单个 EXE，也不要将不同版本的 EXE、`.exe.config` 或 `explorer/` 混用。**
5. 请先关闭旧版再启动新版。探索状态库升级为 schema v4（保留历史记录与全盘批次顺序），旧版 Host 不能打开升级后的同一状态库，也不要并行运行多个版本。
6. 若旧版记录缺少性能索引且剩余预算不足，程序会暂缓建立索引，已有记录仍可查看。可到“记录与帮助”展开“高级维护与技术详情”，核对占用后确认调整本次会话记录预算；程序会在空间保护内重试建立索引。此操作不扩大扫描范围，也不授予文件处理权限。
7. 当前构建未做第三方代码签名；不要为了运行程序而关闭系统安全防护。

## 二、主界面：三档快速清理

快速清理在同一主窗口完成“选档 → 扫描 → 查看明细／保留例外 → 确认清理”。

### 1. 选档与扫描

- **低／中／高三档预设**：选择档位即生效（新用户默认**中档**）。普通使用无需逐项勾选规则。
  - **高档零保留期仅限精确纯缓存白名单**：包括 Chrome／Edge／Brave 的 `Cache`、`Code Cache`、`GPUCache`，Firefox `cache2`，VS Code `Cache`／`CachedData`，新版 Teams 的三个精确缓存子目录，以及经典 Teams `GPUCache`。
  - Temp、npm／NuGet／pip／Yarn／Go／Gradle 等包与构建缓存、崩溃转储／WER 归档、显卡着色器缓存等仍保持正数保留期；**零保留期不绕过进程关闭、文件占用、只读、链接、未来时间和文件身份检查。**
  - **高档包含崩溃转储与 WER 归档**，清除后不可重建，会失去历史故障诊断资料；包／构建缓存与浏览器缓存清除后可能触发重新下载或重新编译。
- **开始扫描**：显示真实已检查文件数（含不符合条件的普通文件，不代表可清理量）、已发现候选数与用时。切换档位或规则后，旧扫描结果立即失效，必须重扫。

### 2. 高级自定义、发现缓存位置与系统维护

- **高级自定义…**：默认关闭，重启后不自动启用；资源管理器图标／缩略图缓存仅在此入口提供。弹窗内编辑的是草稿，点击“确定”才应用；取消或按 `Escape` 键不会改动现有范围，未修改规则时也不使已有扫描失效。
- **发现缓存位置…（只读）**：仅从当前进程环境变量 `NUGET_HTTP_CACHE_PATH` 和 `PIP_CACHE_DIR` 只读发现受支持布局（NuGet HTTP；pip `http`、`http-v2`、`wheels`），不遍历配置文件、不接受任意手动路径、不执行 Python／pip／NuGet。发现不等于授权，必须在弹窗内确认绑定；来源、路径、目录身份或布局变化后自动失效，也可随时撤销。
- **系统维护…（独立高级入口）**：唯一动作为系统自带 DISM 的 `/Online /Cleanup-Image /StartComponentCleanup`（不含 `/ResetBase`）。点击后先显示风险说明（旧组件可能立即清理、影响更新回退，释放量无法事前统计），用户显式确认后才由 DISM 请求一次 UAC；本清理器自身不提权。在说明窗取消不会触发 UAC 或 DISM。

### 3. 查看明细、保留例外与清理执行

- 扫描完成后可点“查看文件明细”打开分页列表，将不希望处理的文件或规则设为**保留例外**，也可导出完整 CSV（仅导出至安全目录中的新文件）。
- **注意**：仅勾选复选框不会缩小快速清理范围，**设为保留例外才会被排除**。执行前请认真核对确认窗口的对象数量、方式与影响；移入回收站通常不会立即释放磁盘可用空间，“已处理逻辑大小”也不等同于实际磁盘剩余空间增加。

## 三、深度探索：8 种分类说明

在主界面点击“深度探索…”打开独立工作台。深度探索先盘点本地元数据，再按结构证据分析。

| 界面分类 | 含义 | 是否能通过深度探索处理 |
|---|---|---|
| 缓存 | 符合当前受支持缓存结构且证据闭合 | **可能可复核**；不是分类出现就能删，仍须看该行状态 |
| 构建产物 | 受支持项目中，可证明由构建产生的限定输出集合 | **可能可复核**；移除后可能要重新构建，程序可能暂时无法启动 |
| 安装包重复 | 对受限 `.zip`/`.msi` 做完整哈希得到的重复组 | **仅整理展示，不可进入回收复核**；显示保留副本不等于已获删除授权 |
| 用户数据 | 命中个人文件、数据库、备份等保护规则 | **不可处理** |
| 混合内容 | 输出中混有受保护内容、未知文件或覆盖不完整等情况 | **不可处理**；不把“剩下看起来像缓存的部分”单独捞出来删 |
| 便携程序 | 可执行程序与便携配置组合，可能就是完整软件 | **不可处理**，不能当作卸载残留 |
| 仅空间展示 | 大文件等空间线索 | **不可处理**；大不代表垃圾 |
| 未确定 | 证据不足或尚未识别 | **不可处理** |

列表中还会显示“未确定”“建议复核”“整理机会（仅展示）”等级别。只有**状态明确为可进入复核（默认未勾选）且允许勾选**的行，才可加入复核清单；灰色或不可选项不要尝试绕过。

## 四、深度探索的当前探测范围

启发式探索不是通用垃圾识别器，也不使用大模型。它按结构线索、已观察空间与检查成本安排有限只读调查，目录名、文件年龄和体积都不是可删授权。

### 1. Chromium 旧式块缓存

只支持含 `index`、`data_0` 到 `data_3` 及 `f_十六进制名` 等严格布局且 `index` 头符合要求的目录。额外文件、子目录、用户内容或覆盖缺口会阻断该组。**不代表所有 Chrome／Edge 缓存、现代 Simple Cache、Service Worker 或整个浏览器用户目录都受支持。**

### 1.1 Chromium Simple Cache v5（只读试点）

识别严格命名的 16 位十六进制 `_0`/`_1` 条目并核对版本 5 固定头尾与流布局算术（每个 `_0` 最多读取 72 字节、`_1` 最多 48 字节），不读取 key、访问网址、HTTP 头或响应正文。**即使界面归类为“缓存”，该试点目前仍为“整理机会／仅展示”，没有候选文件，不能进入回收复核。**

### 2. .NET bin/obj

需同时满足受支持 SDK 项目标记及限定输出成员（符合条件的 `.dll`、`.pdb`、`.cache`、`project.assets.json`、`*.deps.json`、`*.runtimeconfig.json`、`*.nuget.dgspec.json`）及完整集合／执行前检查。混入 `appsettings.json`、任意可执行程序或手写源码时整组拒绝。**不要依据此类名称手工删除软件安装目录中的 DLL。**

### 3. 受限前端 dist

当前识别特定 Vite 构建布局（`dist/index.html` 与 `assets` 内带哈希命名的 JS/CSS）。额外图片、字体或静态资源可能使整组拒绝，不支持所有前端框架或自定义脚手架。

### 4. 重复安装包与大文件

仅对受限 `.zip`/`.msi` 头、大小与完整 SHA-256 进行重复线索核验；结果仍**仅展示**，普通压缩包可能装有个人资料，重复或大文件均不代表可删。

### 5. 与快速清理的边界区别

某个位置在快速清理规则中受支持，不代表深度探索一定会识别；反之亦然。两套流程的候选与确认完全独立。

## 五、深度探索扫描范围与全盘批次

### 所选文件夹或单盘

使用路径框输入／浏览目录，或通过“快速选盘”下拉框选择盘符（即使初始已显示 `C:`，再次确认同一盘也会把 `C:\` 写入上方路径框；按 `Escape` 取消菜单不覆盖现有输入）。选盘不自动扫描，点击“开始探索”才启动盘点。

### 全盘扫描（固定磁盘逐盘串行）

- 按开始时获取的所有可用固定磁盘**逐盘串行盘点**；默认不含 U 盘与网络盘。系统保护区、其他账户、无权限、链接／重解析点、离线云占位等位置仍会跳过，“全盘”不代表无遗漏读取每个文件。
- 每个盘各自持有独立的任务、盘点版本、建议与批准集合，不会自动分析或跨盘批准删除。
- **暂停／继续／取消／关窗**：暂停保留当前进度；继续会重建该任务的观察代次（非逐字节断点续扫）；取消停止当前及后续未扫盘；关窗停止推进并保留已完成盘记录，不会在后台继续扫下一盘。
- **关窗或重启后继续批次**：在“历史任务”页下方的“全盘批次历史”选中条目后点“查看所选批次（只读）”，回到盘点页点“继续剩余扫描…”并核对完整根路径、状态与版本后再确认推进。原卷身份变化、换盘或磁盘不可用会保守停止，不静默改扫替换磁盘。

## 六、从盘点到复核回收：操作步骤

1. 打开“深度探索…”，选定范围后点击“开始探索”。
2. 观察盘点状态与覆盖统计：
   - 大盘盘点耗时较长，“已观察量”不代表剩余百分比；界面同时显示本轮用时、近期约多少对象／秒及最近推进时间。请求较久时可能提示“等待扫描服务回应”。
   - **`Ready`** 表示盘点结束；**`Partial`** 表示存在覆盖缺口，界面会按链接／云占位、保护位置、元数据不可读、目录不可读等安全分类展示计数。**`Partial` 不等于失败项已解决，未覆盖对象绝不会成为处理候选，已覆盖并可核验的分支仍可继续分析。**
3. 若分析阶段提示可用内存不足，**无需立刻重跑全盘盘点**：既有扫描记录会保留，可直接回到盘点页选中较小的子目录后，点击“只分析所选目录”。（也可点击“自动深入整个范围”，该按钮只分析当前选中的单个任务范围。）
4. 分析预算用尽可能仅完成部分调查；没有建议不代表没有磁盘占用，也不代表其他文件绝对安全。
5. 仅勾选确认愿意回收的“可进入复核”组，查看候选文件与影响后点击“生成复核清单…”。后台准备期间会显示已核查进度与用时，支持点击“返回修改”取消并调整选择。
6. 进入复核页后（在应用允许的最小窗口尺寸下也可正常查看文件列表），逐项核对路径、数量、逻辑大小和清单指纹；确认无误后再依次执行：
   - **第一步：确认此清单**（仅持久化批准，不移动文件）。
   - **第二步：移入回收站…**（另有确认框，实际请求移入系统回收站）。
7. 若执行结果出现部分失败、取消、中断或“结果未知”，请按实际汇总核对，切勿将未确认项视作已清理。点击“查看逐项记录…”可分页（每页 64 条）查看只读台账；同一对象可能先后记录尝试意图与最终结果，汇总以每个对象最后一条记录为准。

## 七、记录、限额与“记录与帮助”页

默认不限制历史任务条数，任务历史与全盘批次历史分别分页（页数不代表总条数）。在深度探索最后一页“记录与帮助”中：

- **常规视图**：显示本程序本地扫描记录的当前占用与会话预算上限（例如 `1GB / 5GB`），说明占用充足时无需维护；遇到异常可点击“保存问题报告…”，选择不存在的新文件导出脱敏诊断信息（仅含版本、状态、安全原因码、数值预算与执行计数，不含本机路径、文件正文、任务 ID 或账号令牌，不自动上传）。
- **高级维护与技术详情**：
  - **本次会话记录空间预算**：可在 `512–16384 MiB` 之间调节（默认 `512 MiB`，重开探索服务恢复默认），不限制总文件数，另受至少 `256 MiB` 磁盘余量保护。
  - **释放所选（已结束）任务…**（历史页）：仅移除程序保存的盘点记录，不删除磁盘上的任何用户文件。
  - **整理扫描记录占用…**：停止活动任务与批次后，先创建并校验包含四类事实的私有备份再整理数据库；**私有备份不会自动删除，仍占磁盘空间**，整理过程可能需要额外临时空间。
  - **重置已结束的分析…**：释放内存会话（上限 8 个）并使旧建议、旧复核清单与未执行批准失效，保留扫描历史、防重放记录与执行账本，不删除磁盘文件。
  - **整理未确认清单…**：将可证明未确认且已失效的旧草稿移入私有保留区，保留区仍占用磁盘空间。

## 八、常见疑问：为什么看到项目却无法清理

| 情况 | 原因与处理方式 |
|---|---|
| 混合内容、用户数据、便携程序 | 受保护类别；切勿尝试绕过 |
| 安装包重复或大文件、Simple Cache v5 | 仅作空间或整理提示；不支持从探索入口回收 |
| `bin`/`obj`/`dist` 不可勾选 | 可能混入额外文件、布局不匹配或存在覆盖缺口；不能只看目录名 |
| `Partial` 或分析预算耗尽 | 仅形成部分证据；保留现有扫描记录，改选更小明确目录继续分析即可，不可将缺口视为安全 |
| 扫描后目录或文件发生变化 | 精确集合指纹失效，整组拒绝；需重新盘点或分析，不自动处理剩余项 |
| 文件只读、被占用、链接或云占位 | 保守跳过；请先手动关闭对应应用，程序不强制结束进程或清除只读 |
| 探索服务不可用或版本冲突 | 核对主程序同级 `explorer/` 与 `.exe.config` 是否完整且版本一致，关闭旧版后重开 |
| 触发索引空间配额限制 | 并非用户文件被删；可在“记录与帮助”调整本次会话预算或释放不再需要的已结束记录 |

## 九、使用建议与已知验证边界

- **建议先从小范围开始**：首次使用先选择一个自己熟悉用途的子目录体验盘点、分析与复核流程；重要项目请务必做好独立备份，并在确认可重新构建后再清理构建产物。
- **未在自动验证中实跑的范围**：本产品未将真实用户缓存删除、真实非空回收站清空、真实 UAC／DISM 系统维护、完整多 DPI／多显示器矩阵或全盘真实文件内容分析作为自动验收认证。人工沙箱、元数据保护回放与受控界面回归不等于对所有真实电脑环境的零缺陷保证。
